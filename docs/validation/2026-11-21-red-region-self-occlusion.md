# 红区有空位却要求暂放的现场复现

实际任务是将全部六件物品放到各自默认区域。绿块已完成，红块被夹起到红区上方，但放置前检查与随后一次持物观察均报告观察路线与实测障碍重叠。模型因此请求先暂放红块，并未得到“红区容量已证为零”的证据。

## 根因与修复

本次相机的红块与桌面苹果形成连通实例，被形状分类误认为高达 186 mm 的 `partial pear`。其中心约为 `[0.1594, -0.3412, 0.1865]`；真正的梨位于黄块上，远离红区。按当前 red 类别排除持物无法删除这个跨类别自身片段。它的障碍体积覆盖路线起点，所有新观察路线因而同时被拒绝。

持物深度过滤使用源相机抓取测量、当前机械臂 TCP 和夹爪开度，先在三维点层分离已知自身，再对环境重新分割。原始帧继续用于可见性及水果夹内标定。源箱体可使用静态实心形状先验；曲面和未知形状须有源实测表面邻近证据，缺云时仅过滤已知手指。真实邻物、香蕉凹处与梨肩部包围箱空角保留。没有扩大碰撞阈值或用模拟物体位姿参与规划。

另外保留三个独立失败检查：放置拒绝、几何容量三态、观察路线拒绝。它们通过动作结果、历史及模型上下文传递，防止最后一个观察错误覆盖原放置依据。

## 证据

- 相同 MuJoCo 快照、相同相机姿态能重现原 `partial pear`。移除 22349 个已证实自身深度像素后，伪梨消失，桌上的苹果恢复为有效测量（置信度 0.992），其他边缘碎片保留。新苹果与旧伪梨相距约 15 mm，已有跨类别空间关联自然替换旧缓存，不需全局忽略无效目标。
- 以真实双指接触恢复本次持物，使用生产 `SkillExecutor.place` 放到原红区。最终相机中心约 `[0.2215, -0.3141, 0.0505]`，红块与苹果同时保留在区内；执行、重力接触、稳定性及相机核验全部通过，红块最终倾斜为 0°。未执行暂放或移动苹果。
- 核心过滤、首次搬运回调、原始帧保留、容量语义、主动观察、范围、确认及编排组合 **297 项通过**；球体夹内标定、恢复边界及持物路径相关组合另 **30 项通过**。两组文件不重叠。
- 保场恢复独立验证保持全部六目标、20 条对话及 3 条操作历史。真实夹持自然稳定 2 秒后仅漂移 0.021 mm。日志重建抓取的附加舍入几何误差上界为 0.194 mm；此为重建误差，并非总传感器精度。后续动作仍需重新通过相机与全路径检查。

全部复现与验证在独立会话中完成，未调用在线模型。原始对话、图像和物理快照只存私有诊断目录，不提交仓库。当前网页现场的保场部署须取消旧待批暂放方案并重新观测环境，不自动执行搬运。

## 现场启用

8767 网页服务已保场切换到修复版本，并仅静止重新拍摄一次（机器人动作指令新增为零）。HTTP 核对确认：红区假梨已移除、苹果测量有效、红块仍由真实双指接触保持；全部六目标、20 条对话和 3 条技能历史原样保留，旧暂放确认已失效，可继续原任务。部署后的物品最大位置变化为 0.021 mm。未自动搬运，也未新增模型请求；网页、脚本和观测图像均返回 200。
