# 六物品任务的真实闭环验证

本轮由主助手直接完成，没有使用子 agent。在线模型产生技能计划，目标位置来自实际 RGB-D；抓放通过生产技能、关节逆解、MuJoCo 动力学和双指接触执行。最终成功同时要求相机确认和逐件物理核验。

## 验证范围

- 随机任务采用固定种子 7、19，记录初始摆场。随机中心范围为 X=[0.18,0.48]、Y=[-0.24,0.24] 米，朝向随机；编辑器检查六件物品不重叠，中心距离还需大于两物品各自包围框最大边的一半之和再加 20 毫米。这是摆场的中心距离余量，不等同于严格保证表面间隙 20 毫米。该设置用于验证普通独立抓取，不代表任意拥挤布局。
- 叠放任务先实际抓放梨子到黄色方块，再下达第二条指令。固定布局为红块 (0.12,-0.37)、苹果 (0.22,-0.32)、绿块 (0.12,0.37)、香蕉 (0.54,0)、黄块 (0.25,0)、梨子 (0.35,0.14) 米；香蕉朝向为 π/2、梨子为 0.3 弧度。
- “全部归位”保留六个原目标；未可靠识别的目标暂缓，不以删减清单结束。已经满足目标的物品可以跳过，因此六件全部通过不代表必须搬运六次。
- 隔离测试预先授权临时腾挪，但仍经过并记录生产审批流程。网页里的真实用户操作保留审批，不自动代替用户同意。
- 耗时从提交指令开始，包含模型响应和动作规划，采用未按现实时间等待的物理仿真；不含首次准备相机扫描。任务中的“全场扫描”为 0 不表示系统从未进行首次观察。

## 修复的机制

1. **锥形夹持与抬升**：原检查只看抓取处；竖直抓取后，抬升可能使两片夹指处在不同高度，导致梨颈滑移。现在同时评估抓取和抬升，释放端也优先选择双指高度更均衡的切向夹持方向，再兼顾源转角。替代方向仍须通过原有截面、邻物和逆解检查。
2. **夹内位置反馈**：台面曲面抓取也检查开度变化，两帧深度图校正夹内平移。源点云可验证球面主体和复合实体，避免把梨颈背面误当作新障碍；不会填满物品外接框中的空角。
3. **观察路径**：相机运动也可能碰倒已叠好的物品。现在检查空爪关节扫掠，并以受测源几何和释放变换临时覆盖刚放下的物品。夹指与掌部分别检查，圆形物体不使用旋转方框的虚构角点。
4. **遮挡的底座**：居中的梨子几乎遮住整个黄色方块顶面。新增实际竖直侧面证据，区分相接侧面的法向；以物品库几何提出高度假设，再重新识别上层。底座保持不可抓取状态，最终接触和稳定性仍由独立物理审核确认。
5. **空位搜索**：避免把一次预算都消耗在同一个位置的多个转腕姿态，或相邻几毫米的失败点。共享区域优先分散落位；理想相机位姿不可达时可使用经过完整路径检查的关节视角。
6. **审核连续性**：保留未搬动物品的核验证据，搬动物品及其依赖叠放目标失效。每次复用仍检查真实支撑、静稳和区域包含关系；人为扰动和意外位移使旧证据失效。复位中的轴对称物品不再因图像主轴改变而重复操作。
7. **计算与停止**：规划器采用驱动器的实际关节范围；取消传入迭代逆解。真实会话按工作线程计算时间分配预算，另有墙钟上限；新受检视角留有处理新测量的额度。观察避障复用向量化的多边形分离检查。
8. **观察后的持物回程**：新的观察位到放置上方的回程同样使用完整受检路线，不能绕回未经检查的关节运动。锥形接触优先均衡双指高度，并避免观察时过度折弯；圆形持物沿用完整圆形棱柱，避免外接方盒角点造成假障碍。局部观察候选覆盖全部原始观察方向，不再仅围着两个近邻视角搜索。
9. **释放前的新反馈**：两帧测量发现夹内平移超过 3 毫米后，保持闭合，至多重新规划一次完整的局部落位流程，再次测量后才允许开爪。低位退出仅可沿受检竖直路径脱离桌面接触；不允许借此水平拖动物体或降低邻物碰撞检查。
10. **局部审核与批准**：每件物品保留自己的落位观察提示，仅作相机瞄准，不能证明任务完成。明确主目标的临时腾挪可以提出完整方案并审批，不必为未指定的障碍终点先停止澄清；位于风险动作之前的显式询问不再额外触发同一方案的总审批。`verify` 明确为后置断言，不能在已知待搬运目标之前当作状态查询。
11. **观察起点的安全余量**：原网页现场的空爪实际未碰撞，却已经位于额外的安全余量内，旧检查使所有退出路线都失败。现在仅对第一段向上退出允许受检的余量恢复：实际实体始终保有间隔、邻近部位不得下降靠近，终点必须回到完整安全间距。原现场精确回放的物品最大位移为 8.32 微米；全场刷新也不能跳过相机运动检查。

## 重现

在项目根目录使用已安装物理依赖的 Python：

```powershell
$env:PYTHONPATH='ws/src/cube_task'
& '.venv-physics/Scripts/python.exe' -m cube_task.tools.assistant_bench `
  --cases 1,4 --seeds 7,19 --output local_validation/typical_tasks_replay --timeout 1200
& '.venv-physics/Scripts/python.exe' -m cube_task.tools.assistant_bench `
  --cases 2,3 --seeds 7 --output local_validation/typical_stacks_replay --timeout 1200
```

这会使用当前在线模型设置并产生实际 API 调用。测试输出含模型回复、场景检查点、调试深度帧和本机诊断，不应提交到公共仓库。当前证据目录 `local_validation/typical_tasks_20261122/` 已加入忽略规则；改用其他输出目录时也应自行保留为本地记录。

已运行的针对性回归覆盖完整目标审核、暂缓、源测量、观察路径、夹持校正、释放姿态和退出路径；主要集合为 579 项通过，后续的 45、55、51、64 项集合含重叠，不能直接相加。最终另重跑 `test_assistant_targeted_scan.py` 与 `test_assistant_source_observation.py`，68 项通过。物理重放结果与这些测试分开记录。

## 未通过的记录与现有限制

- 在较早的同一随机种子 7 归默认区运行中，720 秒上限触发时仅 5/6 物品物理到位，苹果仍在夹爪中，无掉落。随后用 1200 秒上限重放才在 805.30 秒完成。不能把延长测试超时作为提速结论，也不能隐去这次未完成记录。
- 初始基线的一次相同随机任务耗时 807.72 秒、调用模型 10 次，只有 2/6 完成。后续通过记录的模型调用降为 2 次，但测试并发与浏览器预览负载不同，不能据此声称固定加速倍数。
- **执行仍是分钟级，尚未达到实时或普遍流畅。** 当前收益主要是避免重复全场扫描、复用仍有效的核验、跳过已到位目标，以及降低无进展的重复决策。没有调低碰撞、支撑或静稳标准来换速度。
- 原网页现场是额外的、未计入上表通过场景的持续任务。安全余量退出修复后黄块已搬运，梨子也已实际抓起，但随后多次持物落位搜索达到预算；期间还发生一次模型接口连接失败。续接后模型提出先安全暂放梨、再抓取到绿色区域，现有流程等待人工确认。**该原现场尚未完成，不能用隔离场景通过替代。**
- 对原现场之前的空爪检查点另做了源测量诊断：固定相机扫描仍会留下不完整轮廓；一次额外观察虽见完整梨子轮廓，夹持截面检查仍拒绝其锥度。说明“识别到物品”和“具备安全抓取测量”必须区分，不能仅凭网页的 `valid` 状态盲抓，也没有把未验证的补视角假设当作已修复功能。
- 在线模型会改变步骤选择、等待时间和审批需求。本轮通过的有限布局不能保证所有密集摆场、任意人工扰动或每次在线回复均成功；新现场失败须保留完整目标及夹持状态继续诊断。
