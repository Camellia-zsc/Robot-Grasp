# 黄色放置与模型恢复验收

日期：2026-11-16。最终运行地址：<http://127.0.0.1:8767>。

## 用户故障

故障现场保存在 `yellow_red_issue_before.json`。红色区域已放入红、绿两个方块，黄色已夹住，第三次动作停在放置下降阶段，结果为 `release / holding_object / fault=true`。

原日志显示第三个放置点为 `[0.215,-0.400,0.0182]`。SafeArm 在下降插值约 14% 处拒绝 `tcp y=-0.400 outside workspace [-0.400,0.400]`，随后向上恢复在约 50% 处被同一边界拒绝。目标点恰好压在边界，测量位姿/FK 残差使路径越界；该错误不表示红区装不下第三个方块。

## 修复与恢复流程

1. 放置规划给水平工作区边界预留 2 mm 余量，避开原来恰好压边界的位置，不放宽 SafeArm 限制。
2. 恢复搜索在生成候选位置时先过滤工作区外的位置，再做占用、夹爪间隙、IK 和实际路径检查，避免边界候选耗尽重试预算。
3. 保存本次抓取的相机测量目标、邻居和抓取姿态。持物时只静止拍摄，模型选择保持夹持的放置续接；不先张爪、不重复抓取、不改放置区。
4. 空夹爪的可恢复失败重新完成六视角扫描后重试原目标。模型只返回本地选项编号，不能提供任意坐标或关节命令。
5. 每条指令最多增加 3 次实际模型请求。成功须通过执行结果和独立落位检查；模型建议停止、取消、API 错误或没有新可行规划时结束并保留现场。每次尝试和公开回复在界面实时显示。

首次在线恢复联调正确得到模型的持物恢复决策，但暴露了候选搜索预算问题。失败记录保留在 `capacity_recovery_online_first_failure.json`，随后增加候选生成阶段的工作区过滤，并扩展回归到真实拥挤场景，最终在线联调通过。
