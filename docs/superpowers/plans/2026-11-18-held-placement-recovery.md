# 持物恢复实施计划

**目标：** 修复黄区边缘观察失败，提供持物暂放、局部重排、重抓原目标及人工确认。

**结构：** observation helper 与 `_before_release` 修复观测路径；runner 提供保留实际抓持变换的严格暂放接口；独立 held_recovery 模块生成与执行有界事务；controller 负责确认等待与原任务队列；前端显示方案问答。

- [x] 保存真实现场与日志，禁网复现 IK 拒绝，对照观察可达性与区域真实容量。
- [x] 为观察抬升增加安全可达的替代路线，保持持物完整包围盒和路径检查，验证原现场。
- [x] 添加持物转移纯规划/执行接口；暂放作用域不能沿用原目标的放置回调。
- [x] 添加暂放重抓和暂放后单物体重排方案，保留原目标、已完成目标与失败收尾记录。
- [x] 添加绑定请求及场景的人工确认 API，支持同意、拒绝、停止和变化过期。
- [x] 增加方案问题及步骤卡片，继续显示模型流式回复，测试真实事件监听器。
- [x] 原现场与新事务的禁网真实链路验证、必要旧回归、独立审查；分功能提交推送并保留现场部署。

验收记录：`local_validation/持物暂放与人工确认验收.md`、`held_recovery_validation.json`、`held_recovery_deployment_check.json`。最终 527 项单元回归、1 项原现场确认后重排执行、9 项既有真实执行及 254 条界面断言通过；本机持物现场已保留部署，代码提交 `cfc72b2`、`c872103` 已推送 `main`。
