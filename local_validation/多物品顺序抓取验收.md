# 多物品顺序抓取验收

日期：2026-11-17。入口仍为根目录 `启动智能抓取界面.cmd`，地址 <http://127.0.0.1:8767>。本记录区分本地真实仿真、固定模型响应测试、前端模拟交互和真实在线模型联调。

## 使用与执行范围

一条命令可选择一个物品，或生成 **2–6 个不同物品**的顺序清单。例如：

- “依次把苹果和香蕉放到红色区域”：苹果完成后再处理香蕉。
- “先把苹果放到红色区域，再把梨子放到绿色区域”：逐件使用不同目的区。
- “把所有物品放到各自默认区域”：只选择当前已观察、有效且类别和区域已确认的目标。苹果默认红区、香蕉默认黄区、梨默认绿区，方块默认同色区域。

正常任务只请求一次模型生成完整计划，本地先核验清单中所有项目，再逐件执行。每次动作后沿用适配器重新扫描；下一件必须从最新场景中，以类别和初始实测位置唯一匹配，重新取得编号、场景版本和几何；若没有新扫描则主动补扫。不能循环使用首次计划中的过期编号，也不能只按类别替换为其他目标。

当前编辑器仍限制每类一件、总计六件；这与执行协议按不同观测 ID 区分物品的规则不同。批量期间整条指令保持忙碌，禁止重复提交或摆场。停止按钮取消剩余任务，已经完成的项目保留。单物品、存在性和位置查询沿用原流程；不支持同一条命令中把同一物品反复搬到多个区域、堆叠、任意坐标或关节指令。

## 反馈与异常

顺序面板显示总件数、已完成件数、当前项，以及等待、重新观测、抓放、恢复、已完成、已在目标区、失败、已取消等状态。目标高亮使用当前执行项的新编号；重新观测、结束、失败或停止时不会退回上一件的旧编号。

物品的保守完整足迹已经在指定区域内时可跳过，计入完成数；仅测量中心位于区域内不足以跳过。正常抓放仍必须通过执行结果和独立落位核验。每件失败后最多请求三次模型恢复；恢复失败、目标漏检或歧义、API 错误、停止都会终止后续项目。若已经独立落位、但机械臂后续动作异常，则保留异常并停止队列，不重复抓取已经完成的物品。

在同批存在同类不同 ID 的情况下，身份匹配还会保守排除本批已完成同类所在区域及 40 mm 余量，避免后项漏检时把已完成物品当成下一件或恢复目标。无法区分时停止。这是基于本批历史与实测区域的保守保护，不是持久视觉身份跟踪。

每批计一次用户请求，全部完成或确认已到位才计一次用户成功。正常只有一次初始模型计划请求；异常恢复的请求另按实际次数计数。页面刷新、相机预览与逐件动作不逐帧调用模型。

## 已取得的验证证据

`ws/src/cube_task/test/test_assistant_batch_simulation.py` 中的两组参数化控制器仿真均已通过：

| 顺序 | 放置要求 | 核验 |
|---|---|---|
| 苹果 → 梨 | 苹果到红区，梨到绿区 | 两次执行、两个独立落位结果均成功 |
| 苹果 → 梨 | 两件均到红区 | 同区顺序放置成功，第二次动作不改变已放置苹果 |

两组都通过实际 `DashboardController`、RGB-D 渲染、运动学规划、IK 和独立落位检查执行。只有最初的模型计划由本地固定测试客户端提供；该客户端根据本次相机检测生成 ID，不提供后续位置或编号。两组均核验初始决策客户端只调用一次，第二件使用第一次动作后新扫描的编号与场景版本；两次动作后苹果位置一致。

最终八个协议、队列、身份、控制器与恢复测试文件的组合为 **242 passed in 5.51s**。覆盖不同 ID 同类物品、漏检时不替换已完成同类、无持物恢复不重抓已完成同类、旋转区域及 40 mm 边界、区域信息异常、跨类别保护和新指令状态隔离。两组完整批量仿真为 **2 passed in 121.16s**。

原有单件与恢复生产仿真回归为 **10 passed in 656.84s**，包括相机扫描、重新抓取、独立落位核验、停止保留夹持、空抓重试和持物恢复。以上合计 254 项 Python 测试通过，另有下述 50 项前端模拟断言。

前端 Node 模拟 DOM 的 **50 项断言通过**，覆盖队列顺序、完成数、各项状态、跳过、失败取消、停止、当前新 ID 高亮与真值视图映射、原单物品兼容和帮助示例。可复用入口为 `ws/src/cube_task/test/test_assistant_batch_ui.cjs`。JavaScript 语法与差异检查通过。前端仅进行了模拟 DOM 验收，没有真实浏览器点击、拖放或截图验收。

另已验证一次真实在线清单生成，证据为 `batch_online_plan_check.json`。使用当前配置和现场第 32 版相机观测，发送“先把苹果放到绿色区域，再把梨子放到红色区域，一件一件抓取。”，真实 `ModelClient` 返回严格的两项 `pick_batch`：先苹果到绿区，后梨到红区，编号均与本次场景一致。耗时 6.31 秒，收到 70 个流式片段，仅一次 API 请求；记录为 `ok=true`、`moved_simulation=false`，没有调用机械运动或修改现场。

当前证据分别覆盖“真实在线模型生成正确清单”和“固定本地意图驱动生产控制器完成两组真实仿真”。**尚未将付费在线模型与生产界面机械运动放在同一条任务中完成端到端联调。** 上述在线清单检查会产生一次中转站费用；此前单香蕉在线抓放证据见 [多物品摆场与抓取验收](多物品摆场与抓取验收.md)，不能替代完整的在线批量机械执行验收。

## 复验与限制

在 `ws/src/cube_task` 运行：

```powershell
python -m pytest -q test/test_assistant_batch.py test/test_assistant_batch_llm.py test/test_assistant_batch_simulation.py
python -m pytest -q test/test_assistant_batch_identity.py test/test_assistant_server.py test/test_assistant_scene_server.py test/test_assistant_llm.py test/test_assistant_recovery.py test/test_assistant_recovery_workflow.py
node test/test_assistant_batch_ui.cjs
```

这些测试使用本地固定模型响应，不请求在线模型。若在界面发送批量抓放指令，则会使用当前配置的真实中转站，按其价格计费。

仍为运动学与几何抓取仿真，未模拟接触摩擦、力觉、刚度或真实滑移动力学，也没有接通 Gazebo 与 MoveIt2 的完整物理闭环。顺序执行不能保证任意摆场、遮挡和拥挤放置均成功，感知、身份、工作空间、IK、夹爪空间及落位检查仍可能保守停止任务。
