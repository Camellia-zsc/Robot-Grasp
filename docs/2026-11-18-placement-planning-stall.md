# 香蕉持物放置搜索卡顿修复

现场最后一次静止观测在 13:02:04，后续直到 13:07:33 才返回停止结果。香蕉已夹持并到达抓取区上方，尚未执行释放。旧日志可定位到观测后的放置搜索，但不能区分当时具体哪一个候选或 IK 求解消耗最多。

离线复现确认：观察姿态搜索在第一次可达性检查收到停止后，仍继续执行了 923 次检查。放置候选重试、倾角/高度搜索、路径预检和 IK 内循环也缺少完整的停止传递。界面同时显示“正在停止”和“逐步执行中”，静止观测完成后没有放置搜索进度。

修复包括：

- 让停止信号贯穿候选、观察视角、路径和 IK 计算；取消后不发布释放计划、不新增运动或松爪。
- 观察姿态按需生成和消费，找到可执行视角后观察，不提前为凑齐一组可达姿态反复求解。
- 合并观察视角的支持点投影，保持原有评分与排序。924 个候选逐项对照一致；本机带相机参数的对照从约 16.8 秒降到 2.4 秒，耗时随机器负载变化。
- 已夹持后的重新规划只调整未来的释放、放置预备和撤离姿态，冻结已完成的抓取变换。
- 单轮放置检查累计计算预算为 45 秒，不累计真实观察移动时间。超时保持夹持并提供可重规划的失败反馈，不清除用户停止信号。
- 显示放置搜索、停止响应和当前仍持物状态。确认选点不等于已经释放或任务成功。

完整轮廓、桌面支撑、夹爪/掌部间隙、路径扫掠、可达性、工作空间余量、新鲜深度可见性、固定点和复位朝向约束继续生效。没有使用仿真世界真值代替相机测量进行规划。

定向验证：规划预算/取消、安全与技能反馈等 99 项通过，持物转运 23 项通过，运动学 10 项通过（5 项需要未安装的可选环境而跳过），真实相机/IK 的四项自适应执行回归通过，持物暂放/移障/重抓回归通过；共 137 项。界面五组测试共 390 条断言通过。当前持物快照的独立重测在约 8.2 秒内确认到可释放方案；这使用重新渲染的 RGB-D 和记录的相机测量历史，不能声称完全重建旧运行的原始深度缓存。

真实服务现场保持 stopped、香蕉夹持、六个物体、26 条聊天及未完成事项；恢复启动校验为零动作、零网络请求，保留精确关节、夹宽、物体和夹持相对变换。公开快照没有原始深度及完整技能执行内存，因此继续保持停止并要求重置。

额外检查发现的既有测试问题：`test_task_grasp.py` 的四项默认高度断言与当前默认配置不一致；`test_placement_workspace_margin.py` 的连续摆放用例仍假定局部观测后能直接取得所有目标。两者在未修改的部署目录 `6e05dba` 同样失败，本次未改动这些旧断言。
