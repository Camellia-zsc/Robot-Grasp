# 全体归位任务错误完成

用户实际指令是“把所有物品放到各自默认区域”。当时现场有红、绿、黄方块、苹果、香蕉和梨六件，首次模型计划却只把香蕉和苹果写入最终 `goals`，仅在说明文字中提到稍后再观察绿色方块与梨。

人工确认没有直接完成任务。记录显示批准后继续执行了香蕉暂放、苹果归位，再重新规划并将香蕉放回黄色区域。错误在于最初两项目标被固定为整条任务的范围；`verify` 与 `finish` 只核验了这两件，随后返回“全部完成”。

## 修复边界

- 明确的全体默认归位指令先绑定实际摆场清单中的全部类别及默认区域。清单仅提供类别和数量，不提供模拟器位置、姿态或抓取许可；配置支持六类也不意味着现场必然有六件。
- 无效、被遮挡或尚未观测到的物品保留为最终待办。每轮步骤可只处理其中一部分，但模型最终目标不能缩小；动作仍须取得唯一有效的相机测量。
- 首次任务与旧任务续接都执行范围绑定。已有目标顺序保持，遗漏目标追加；旧任务已记录的原始物品不会因后续删除而从范围中消失。
- 人工同意仍只授权后续操作，不清除目标、复位义务或制造现场进展。现场变化会使旧计划失效。
- 最终测量与完成发布使用同一份完整清单，包含额外原位复位义务。聚合 `success` 或只覆盖两件的缓存证据不能替代六件的逐项核验。
- 明确子集、仅可见物品、否定/查询、原位恢复与默认区域归位保持区别。礼貌的行动请求和“完成后检查”不取消全体范围。没有明确匹配全体默认归位语义时，继续使用现有语义规划，不强加全体目标。

## 复现与验证

离线真实控制器回归先复现三件仅列一项目标、六件仅列两项目标，以及旧 partial memory 续接错误完成。人工批准、批准后现场变化、原位复位义务、单目标缓存、完整目标索引、显式子集均有对应检查。两处独立复审发现的边界也已修复：旧库存被删除后缩水，以及合法的额外复位证据在完成发布时被误拒绝。

核心范围、协议、编排、确认、最终核验、停止、上下文与已完成动作组合为 **276 项通过**。库存与上下文的定向检查另覆盖：隐藏物品仍是目标、库存不含几何、清单不授予动作、冻结范围不因现场删减缩小、部分成功不能发布全体完成。测试组有重叠，不累加为全仓库总数。

从实际保存的六物品及机械臂状态恢复后，用未修改的生产相机核验流程检查完整六项目标，结果正确返回 `verification_incomplete`，不再接受旧的两件成功作为整条任务完成。该次新观测确认苹果在默认区；香蕉在本次画面中未获充分确认，保留为待核验，不据此断言它尚未归位。原有香蕉、苹果动作记录保留，未重抓或重置物品。

本轮没有调用在线模型。原始对话、运行记录和物理快照均保存在私有诊断目录，不提交仓库。
