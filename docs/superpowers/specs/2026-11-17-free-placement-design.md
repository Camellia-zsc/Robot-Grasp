# 抓取区与桌面点选放置

用户已要求实现任意可行位置的抓放，并已授权当前项目的仿真、界面和顺序任务扩展。此前黄色修复已推送至 GitHub `abcedee`。本功能继续在现有工作区实现并分功能提交。

## 行为

保留三色区和默认归类。增加“抓取区自动找空位”和“桌面指定 XY”两种目的地。俯视图新增独立的选择放置点模式；点击只选择目标，不编辑或移动世界物体。当前选择随普通语言指令一起发送，模型实时回复和后续执行流程保持可见。

精确点仅支持桌面平面 XY，不接受高度、关节或任意姿态。目标点必须在公布的配置工作空间内，物品完整足迹须有桌面支撑，并与实测邻物和手指空间保持间隙。执行层继续求逆解并检查运动；不可行时拒绝，不把指定点偷偷换到附近位置。抓取区请求可以在其多边形内选择空位。

## 协议与边界

原 `pick` 与 `pick_batch` 格式保持兼容。单件和批量各项可增加 `destination`：

```json
{"type":"region","name":"pick_area"}
```

```json
{"type":"point","xy":[0.30,0.08]}
```

存在新目标时 `zone_name` 必须为 null；旧请求省略新字段时返回结构和默认区行为不变。严格拒绝额外字段、布尔/字符串坐标、非有限值、越界以及冲突目标。点选位置作为一次指令的只读上下文，不构成执行授权；问句仍只读。编辑、重置和过期选择需清理。

场景公布 `placement` 元数据：配置工作空间、抓取区多边形、点落位容差。模型只接收配置与相机观测，不接收世界物体列表或真值。恢复和批量任务完整保留目标，指定点恢复不能换点；已完成物品按局部放置身份排除，不能排除整个抓取区。

## 实现选择

采用可选结构化目的地并复用既有抓放链路。单纯新增一个固定“抓取区”无法满足任意桌面落点；把所有落点永久写入世界分区会改变比赛计分、物体所属区和默认归类，故采用仅属于当前规划的临时目标区域。世界固定分区保持现有含义。

`assistant/destinations.py` 集中配置边界、目标标准化和观测完成判断。`simulation.py` 重新验证、准备实测占位、目标观测及独立落位核验；`runner.py` 和 `PlacePlanner` 接收临时目标与严格落位规则。原有比赛路径仍使用现有策略。

严格目标需检查旋转后的完整足迹，不能只依赖小于方块角部范围的圆形近似；精确点的逆解退让也不能改变 XY。观测范围和目标视角需覆盖新增落点，以支持之后再次搬走。

## 验收

新增协议、批量绑定/跳过、恢复、目标边界/占位/不可达和 UI 模式测试。真实 RGB-D 仿真验证：从色区搬回抓取区、桌面点放置后再识别搬运、多物品连续放置，以及占位/越界/不可达目标拒绝前未移动目标。最终代码跑原六件回归与新目标流程，记录源码哈希。不得请求收费模型接口进行测试，不操作用户现场；部署时保留摆放、聊天与计数。
