# 人工提前完成任务后的执行守卫

2026-11-18。用户在执行中人为改变布局，可能已把物品放入任务目的地。原技能路线仍会重新抓取；旧宏队列的完成判断没有被带入新的技能执行器。

## 行为

- `move` 在抓取规划前及新抓取观测后检查该步骤的实际目的地。只有当前相机确认唯一目标、完整轮廓与支撑满足要求、独立结果评估也通过时，返回 `skipped=true / already_satisfied`，不抓放。固定点与原位复位朝向仍保留各自约束。
- 明确的 `pick → place` 最终目标组合也可跳过，两处执行边界分别检查。中间的询问、临时放置、独立抓起保持和自动寻找暂放点不会被当成最终目标完成。
- 人工扰动、排队干预、取消、持物、已被动作消费的图像都不能沿用旧完成状态。只在编辑器确认每类至多一件时，忘记该类旧版本源位置记忆，避免局部观测产生虚假的第二个目标；当前版本歧义继续拒绝执行。
- 成功搬放已有相机与独立落位证明时，相同目标的后续 `verify` 和 `finish` 可复用。证明匹配完整目的地合约；每次真实物理动作都清除旧证明，因为机器人运动本身不会增加人工干预版本号。多目标缺项、错误目的地、保护目标及复位义务继续要求新核验。
- 真实多目标核验会按目的地分组输出，完成判断按完整合约匹配，不依赖返回顺序。
