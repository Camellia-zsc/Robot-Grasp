# 重复／混合观测误作目标的修复

2026-11-17，用户报告目标表最下面多出一条不可抓取的梨。

## 原因和复现

捕获的第 26 次场景中，主梨位置为 `(0.1981, -0.0109, 0.1017)`，置信度 0.973；额外梨位置为 `(0.2363, -0.0229, 0.0985)`，置信度 0.646，拒绝原因 `touches_image_border`。两者水平距离约 40.0405 mm，略超原有 40 mm 中心距离合并阈值。

按物品的实际尺寸、位置和朝向重建六视角 RGB-D 后可稳定复现。第三视角的额外轮廓混有梨和旁边绿色方块的表面，不是另一件梨。此轮廓长约 148 mm，明显超过单梨约 76 mm 的测量长度。仅提高置信度阈值或按类别只保留一个实例不能可靠处理这种情况。

## 修复

`assistant/observations.py` 在既有中心距离合并后，仅检查无效候选。它使用同次扫描中其他视角的有效、完整检测，既不接收世界对象，也不使用物品库的数量限制。

- 在每个已确认观测内分别验证：候选点位于实测 XY 凸包和高度范围的 3 mm 扩张内，并距该观测的实际表面点不超过 12 mm。表面距离允许不同视角看到相邻表面，不是放宽原有 40 mm 实体合并距离。
- 各观测的解释结果再联合；不允许借用一个物体的包络和另一个物体的表面。候选按 2 mm 体素等权采样，至少 98% 得到解释，且不存在独立的残余小点簇，才从实体列表中移除。
- 原始各视角的检测与相机图保留，合并依据另记入 `scene.observation_diagnostics`。尚无法解释的候选继续保留；缺点云、非有限数据、同视角或仅有不完整支持时不做该项删除。新规则不删除有效目标。
- 在生成对象编号和执行映射前处理，界面与模型使用同一份结果。界面分别统计确认目标和待确认观测；后者标为“疑似”，说明截断、遮挡等原因，并提示已合并的重复／混合观测数量。

## 验证与预防

- `test_assistant_observations.py`：13 项通过，包含实际六视角的先失败后通过回归、相邻同类、缺失与异常点云、包络内部空隙、不足 2% 的独立未知残余、跨物体借用证据和视角顺序变化。
- 原多视图、物品分类、场景服务、反馈与模型协议相关测试：128 项通过。
- 原助手仿真与自动恢复：10 项通过。
- Python 编译、JS 语法、模拟 DOM 交互与 Git 差异检查通过。本次验证未发起收费模型请求。

此前水果测试只统计 `valid=True` 的梨，因此漏掉了额外无效候选。新回归统计包括无效检测在内的所有梨，并检查模型可执行映射及原始视角保留情况。

这是一项针对有充分相机证据的观测合并修复，不保证未知物体和任意遮挡都能被正确识别。无法解释的轮廓仍需作为待确认观测查看，不能直接抓取。
