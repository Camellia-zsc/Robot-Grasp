# 物理抓取与叠放

交互界面现在默认使用 MuJoCo。物品是带质量的自由刚体，机械臂通过关节伺服运动，双指通过碰撞、接触和摩擦抓住物品。界面中的物品位置是物理结果的显示镜像；不会将物品焊在夹爪上，也不会在释放时直接写入一个“成功位置”。

## 安装和启动

在已有 NumPy、OpenCV、SciPy 等项目依赖的 Python 环境中，安装独立的物理依赖：

```powershell
python -m venv --system-site-packages .venv-physics
.\.venv-physics\Scripts\python.exe -m pip install -r requirements-physics.txt
```

MuJoCo 版本固定为 **3.3.7**，因为现有机械臂驱动使用 3.x 的惯量矩阵接口。界面启动前会检查版本；缺少依赖或版本不符会明确报错。

首次启动可能需要生成物品识别缓存，准备时间较长；后续启动会复用它。物理依赖只改变仿真，不改变已有在线 API 配置。

运行根目录的“启动智能抓取界面.cmd”会优先使用本项目 `.venv-physics`。也可设置 `MUJOCO_PYTHON`，指定已有物理环境的 Python。直接启动：

```powershell
cd ws\src\cube_task
& '<物理环境的 Python 完整路径>' -m cube_task assistant_ui --backend mujoco --port 8767 --open-browser
```

如需复现实验原有的运动学模式，显式添加 `--backend sim`；该模式不提供真实重力叠放。`--fast` 可用于离线验证，它取消画面时间节奏，不跳过物理步或接触检查。

## 夹爪模型

本项目的 `robot.gripper.max_width` 已配置为 **100 mm**。若未单独指定 `sim.mujoco.gripper_max_width`，交互物理环境将此行程写入 MJCF 的真实双指滑动关节范围，保留力限制、接触和摩擦。界面会显示实际物理夹爪行程。

这是项目采用的扩展行程模型。原始 PiPER MJCF 的 70 mm 行程仍可通过 `sim.mujoco.gripper_max_width` 单独配置；真实机械臂的可夹宽度应按实际硬件校验。形状完整性、指尖间隙和碰撞限制不会为了抓住某种物品而取消。

## 使用和边界

- 可输入“把苹果放到红色方块上”。红色区域与红色方块顶面是两个不同的目标。
- 首版支持以相机确认的平顶方块为底座。苹果、香蕉、梨等曲面物品可以作为被放置物；曲面物品暂不作为自动规划中的可靠底座。
- 顶面位置和释放高度来自 RGB-D 测量。释放后会等待落稳，并同时检查新的相机证据、真实物理接触及双方运动速度。
- 偏心、滚动、掉落或人为移走底座会使原完成证据失效。系统会报告现场变化，供后续重新观察和恢复；不会将“动作执行完了”等同于“叠放成功”。
- 重心不必在同一条竖线上；能否稳定由接触支撑范围、质量分布和摩擦共同决定。MuJoCo 会实际积分运动，但这些库物品仍是简化的刚体碰撞模型，尚未模拟水果变形。

梨子采用默认直立的模型，果腹底部有直径 48 mm、高 8 mm 的同色一体平底。
该几何同时用于显示、RGB-D 和物理碰撞，总质量保持 100 g。它提高轻微倾斜和低位
释放后的稳定性；过大倾斜仍会自然倒下。苹果的低位释放对照测试稳定，暂未改形；
香蕉的默认模型就是平放，平放不属于倾倒故障。

混合物品任务使用既有水果任务的 2.5 N 夹持力，并在抬升后更新实测夹宽。已观测
直立梨的计划释放姿态限制相对倾斜不超过 15°，落稳后还须通过实际姿态、支撑和
运动速度检查。圆形果腹核验不再使用随 PCA 朝向膨胀的方形轮廓。完整侧倒梨可被
重新识别，并替换旧位置记忆；只看到部分球腹的图像仍不能用于抓取。

界面和模型会收到“直立／侧倒／正常平放”的相机姿态提示。目前机械臂尚无自动
扶正侧倒梨的动作；模型应请求人工在摆场中拖动梨子重新摆正，再重新观察。该编辑
是明确的人为摆场，不是一次自动扶正成功。严格点位若因手内滑移超出 15 mm 容差，
仍报告失败并交给恢复流程，不放宽容差或写入成功位置。

无需在线 API 的物理验证：

```powershell
cd ws\src\cube_task
& '<物理环境的 Python 完整路径>' -m pytest -q test/test_assistant_physics.py test/test_assistant_physics_session.py
```

验证包含居中叠放、偏心下落、滚动、移走底座、编辑重建、真实夹持和搬运掉落，以及完整的相机识别→抓苹果→叠到红块→移走红块后原目标不再成立。

## 低位释放与任务停止

交互仿真的桌面和叠放任务现在采用 4 mm 计划间隙（包含深度与夹持误差余量）。松手前会复核实际末端位姿并短暂停稳；下降中断且仍明显偏高时会保留夹持，不再从高处松手。

点击停止后，先结束旧任务并保持机械臂。健康反馈确认且旧执行退出后，可直接调整摆场、发送新指令，或点击“继续未完成任务”。存在临时移物的复位承诺时，请使用继续功能保留原任务。持物时可继续放置或使用“运行中干预”移动其他物品；仍不能直接拖动夹着的物品。真正的机械臂故障仍需处理故障或重置。

验证和已知边界见 [低位释放与停止验证](validation/2026-11-19-low-release-and-stop.md)。

## 连续搬运与执行中观察

网页仿真的三个色区现为 30 cm × 30 cm。连续任务会利用机械臂运动时采集的 RGB-D，
更新可见物品，复用未变化的完整测量；画面裁剪或暂时遮挡不会直接抹掉已知物品。
仍缺少完整源测量、支撑或空位视线时，才补充局部观察，最终统一核验全部目标。

区域使用浅红、浅绿、浅黄，与物品保持同一主色系并拉开明度，尤其便于区分香蕉、
黄块与黄色区域。相机画面、物理材质及摆场显示同步采用这一配色。

运行中可切换到干预操作，拖动未被夹持的物品。相机更新后，已经被人工完成的
子任务会跳过；目标区域增加物品时会重新检查落点，全部目标满足后可提前结束。
干预使正在执行的下降、释放或搬运路径失效时，机械臂会先停止该段动作。

界面速度选项控制播放节奏；增加倍速不会跳过物理步、碰撞、夹持或落稳检查。
较复杂布局仍可能耗时于路径搜索或模型响应，刷新频率也与物理积分速度不同。
五类任务的验收与具体边界见 [增量观察验证](validation/2026-11-23-incremental-motion-observation.md)。
