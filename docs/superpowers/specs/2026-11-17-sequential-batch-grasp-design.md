# 多物品顺序抓取设计

用户授权：一条指令允许选择多个物品，机械臂必须逐件执行。本功能延续现有界面、在线模型、RGB-D 观测和恢复流程。

选择一次模型生成有界任务清单，再由本地单工作线程逐项执行。相比每完成一件都重新请求模型，这样少发正常 API 请求、顺序稳定；相比直接循环旧编号，必须在每项前重新绑定当前观测编号，避免使用失效场景。现有每类最多一件、最多六件的摆场限制不变。

协议保留原单物品 pick 与只读响应，增加 pick_batch：scene_version/action/items/message，其中 items 为 2–6 个 object_id/zone_name。全清单先校验，拒绝重复 ID、未知/无效对象、失效版本、未知区域和多余字段；不允许部分非法计划先执行合法部分。模型按用户明确顺序输出，没有明确顺序时按其列举顺序；“全部”只选已观察且确认的目标。若用户指定物品缺失或存在歧义，整条请求应澄清。

队列保留每项目标类别、首次实测 XY 和固定目的区。执行每项前，从最新观测中找同类别且距原实测位置不超过 40 mm 的唯一有效候选，使用新 ID、场景版本和新几何；不存在或多解时停止，不能擅自换物体。每件完成后沿用执行适配器的再次扫描；若场景未更新则主动观测。不给模型或队列注入仿真真值坐标。

如相机已经观测到整个目标足迹在目的区内，可标为无需搬运；检测中心落在区域内不足以跳过。正常抓放须通过现有独立落位核验。失败逐件进入最多三次模型恢复；已独立落位但机械臂后续动作失败时，不再次抓该物品，停止后续队列并保留异常。恢复失败、取消、目标失踪或歧义均终止剩余项目。

界面增加顺序清单：pending/observing/executing/recovering/succeeded/skipped/failed/cancelled，显示当前项、已完成数与每项说明，保留模型流式回复和现有抓取反馈。任务期间禁止重复提交和摆场；停止按钮取消剩余项。一次批量指令计一次用户请求，只有全清单完成才计用户成功；正常仅一次模型计划请求，额外恢复按实计数。

验证包括严格协议、重复/非法项全拒绝、新编号绑定、序列执行、取消和单件恢复、落位后动作异常不重抓、已在区域的实测完整足迹、只读请求不动作；用真实 RGB-D/IK 顺序搬运两种水果回归。更新中文用法与验收记录，提交、推送并保留现场布局重启 8767。
