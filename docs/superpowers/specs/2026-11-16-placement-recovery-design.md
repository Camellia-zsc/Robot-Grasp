# 放置容量与模型恢复设计

目标：验证红区已放红、绿后是否能继续放黄色，并让执行失败能由真实在线模型选择修复动作、执行、核验，成功后结束。

故障已保存于 `local_validation/yellow_red_issue_before.json`。原始第三个放置点位于工作空间边界 y=-0.400 m，实际下降与恢复路径都被 SafeArm 拒绝。先用三次相机实测抓放复现，再在候选放置点选择时留边界余量；不放宽安全检查，不根据仿真物体真值规划。

恢复采用受约束的本地动作选项，而不是让模型输出关节或坐标。模型继续使用实际在线流式接口，接收原目标、失败阶段、相机观测、可选动作、此前尝试，返回当前版本下的选项编号与中文说明。目标物体和放置区不能被恢复决策改变。

空夹爪可重新扫描并重试同一目标。已夹持时只静止拍摄，结合本次指令前的实测占用重新选择放置点，执行保持夹持的放置续接，禁止重复完整抓取、扫描运动或空中松爪。停止和不健康的机械臂不能自动恢复。

每条指令初次执行后最多再交给模型三次；成功以控制器结果和独立落位核验为准，模型说成功不算成功。无可执行方案、模型建议停止、持续失败、取消、API失败均结束并解释原因。夹持时保持现场，不能自动重置。可恢复故障先留在当前任务内处理，最终失败才要求重置。

界面显示恢复编号、失败原因、模型实时回复和每次核验结果；保留停止按钮。额外模型调用计入现有指标，只有最终成功才增加一次成功数。

验证包括：三个实物仿真方块同区且互不相交、原物体不移动；注入一次放置失败后从真实夹持状态恢复；模型虚构选项/改目标被拒绝；取消与连续失败不形成无限调用；真实在线恢复请求与可视化状态接口联调。
