# 多物品交互摆场与形状抓取

用户已选择先扩展现有运动学仿真：物品库、俯视拖放、RGB-D 形状抓取和反馈，不模拟物体刚度。

## 行为

保留默认三色方块，增加苹果、香蕉和梨。网页提供独立俯视编辑区：拖动物品卡片添加，拖动已有物体移动，选中后调整朝向或删除，支持清空。3D 场景与腕部相机显示相同几何物体。物体尺寸固定为库内定义，每类最多一件，共六件；编辑仅允许空闲、未停止且未夹持物体时进行。

编辑请求携带当前场景版本，后端再次校验版本、类型、有限数值、可摆放区域、完整足迹和物体间隙；无效操作不得部分改变世界。编辑成功清空旧观测、选中编号、规划占用和恢复上下文。随后执行指令时重新多视角扫描，不把编辑器的真实标签和位置填进模型的观测列表。

## 感知与抓取

沿用可靠的 L1 世界、机器人、相机和六视角扫描。助手使用独立 Sandbox 任务配置，使三色方块继续采用方块策略，水果采用已有的截面、曲线局部抓点和梨颈策略。运行时分类来自 RGB-D 图像特征；物品库标签仅用于离线合成训练样本。低覆盖或遮挡观测如实拒绝；不通过读取世界真实中心补齐检测。

默认放置区为红块/苹果进红区、绿块/梨进绿区、黄块/香蕉进黄区；用户仍可指定其他已有区域。尺寸和抓取语义来自相机测量及库内类别先验，原有 SafeArm、碰撞检查和有界模型恢复继续生效。

已有闭合、抬升、搬运夹持检查以及放置后的独立几何核验继续使用，界面显示这些反馈和所选抓取的测量尺寸、夹爪宽度与角度。此反馈是运动学模拟检查，不表示力反馈或接触动力学已实现。

## 接口与职责

- `catalog.py`：物品定义、对象构造、编辑范围/间隙校验和原子场景变更。
- `catalog_perception.py`：独立 Sandbox 配置、库内合成 RGB-D 训练和运行时分类。
- `simulation.py`：相机、抓取执行、编辑失效、反馈快照。`edit_scene(request)` 返回失效后的 `scene()`。
- `server.py`：单 worker 执行 `/api/scene-edit`，任务/编辑互斥并显示编辑错误。
- `editor.js`：独立俯视交互；`app.js` 绘制真实形状并传递最新状态。

请求为 `{scene_version, action, catalog_id?, object_id?, xy?, yaw?}`，action 为 add/move/remove/clear，yaw 为弧度。状态的 `simulation.editor` 提供 catalog、pick_polygon、max_objects、scene_version、editable，物体仍来自 `simulation.objects`；模型收到的 `scene.objects` 仅来自相机检测。

## 验收

逐类检验编辑增删移动旋转、越界/重叠/过期版本的原子拒绝、任务执行中禁编辑、旧决策失效。使用真实渲染/感知/IK/技能链验证苹果、香蕉、梨的独立抓放，以及混合物品的识别和不同朝向；付费 API 只用于最终少量端到端检查，不用于所有单元测试。保留已有方块与恢复测试。浏览器验证实际拖放和反馈显示。
